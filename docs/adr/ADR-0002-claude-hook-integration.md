# ADR-0002 — Claude Code hook integration contract

- Date / owner / status: 2026-11-19 / project owner / **accepted** by owner 2026-11-19 (limits listed below still apply)
- Requirement IDs and affected phase: R02, R03, R04, R07; D08, D09; Phase 1 (P1-04, P1-06, P1-08)
- Decision and constraints:
  1. **Exec form only.** Every hook is `{"type":"command","command":"<absolute path to native exe>","args":["hook","<Event>"]}`. No shell form, no `.cmd`/`.ps1` shim, no Node launcher. Setup writes the absolute path; `doctor` checks that it still resolves.
  2. **Documented fields are the primary capture source.** User text from `UserPromptSubmit.prompt`; assistant text from `Stop.last_assistant_message`; tool metadata from `PostToolUse`/`PostToolUseFailure`; compaction from `PostCompact.compact_summary`. `transcript_path` is read only by a later, versioned reconciliation job that fills gaps and never blocks a hook. A transcript parse failure is a recorded capture gap, not an error.
  3. **Synchronous, bounded capture.** Each hook redacts, writes one spool file durably and exits 0. Internal deadline 60 ms for capture, 150 ms for hooks that also return context; on deadline the hook prints nothing and exits 0. Nothing durable is attached to SessionEnd. No `async` hooks for capture. No PreToolUse or PermissionRequest hooks in the core.
  4. **Context envelope with explicit coverage.** Hook output stays under 9,000 characters. It always starts with a manifest: count of active instructions in scope, each instruction's ID and digest, and how many are included in full. Instructions are included verbatim in priority order until the budget is reached. If any are not included, the envelope says so in plain words and names the tool/command that returns the rest. The engine never emits a string over the host cap, so the host's silent file-and-preview path is never triggered.
  5. **Factual wording.** Injected text is presented as recorded user instructions with source and date, not as system commands.
  6. **Data location.** Database, spool and cache live in the OS user data directory. Nothing the user must keep is stored under `${CLAUDE_PLUGIN_ROOT}` or `${CLAUDE_PLUGIN_DATA}`.
- Evidence: `evidence/phase-0/README.md` findings H1–H12 (official hooks and plugin references, checked 2026-11-19) and measured spawn costs H6.
- Alternatives and reasons for rejecting them: Shell-form hooks (69 ms p50 spawn through Git Bash, 190 ms through PowerShell on the reference machine). Transcript tailing as the main path (documented as lagging; format is not a published contract). HTTP hooks to a daemon (makes capture depend on a running server, which is the failure this product exists to avoid). Splitting context across several hook entries to exceed 10 k (documented behaviour suggests it works, but it is untested and leans on an implementation detail).
- Quality, durability, resource and compatibility implications: Assistant turns that end without a Stop event (crash, kill) are recovered only by transcript reconciliation and are otherwise reported as gaps. Instruction sets larger than the envelope need a second step by the agent; the manifest makes that visible instead of silent.
- Security, privacy, licensing and cost implications: Redaction runs before the spool write. Hook stdout carries only the envelope, never logs.
- Migration / rollout / rollback / degradation plan: Hook contract is versioned in the normalized event (`adapter_version`). If a live test shows a field missing on a supported Claude Code version, that event is disabled for that version and listed in `doctor`.
- Known limitations, open questions and next review trigger: Not yet exercised on 2.1.328. Open: whether a 9,000-character factual envelope is reliably followed by the model; behaviour when other plugins also inject at SessionStart (this machine has several); whether the envelope should be repeated on `source=compact`. Review after the isolated fixture run and on any Claude Code minor release that changes the hooks page.
- Update 2026-11-19 (session 2): live print-mode run on 2.1.328 confirmed exec-form launch from `${CLAUDE_PLUGIN_ROOT}`, the five core event payloads, context injection at SessionStart and an 8,903-character UserPromptSubmit envelope, and `Stop.last_assistant_message`. Hook exe measured at p95 14.4 ms from spawn including the durable write. New constraints: `SessionStart` may carry no `model` or `permission_mode`; `transcript_path` may point to a file that does not exist — the adapter must treat every field except `session_id`, `cwd` and `hook_event_name` as optional. Evidence §9.2–9.3. Still untested: interactive mode, compaction/resume, coexistence with other plugins, a full-size envelope of real instructions.
- Update 2026-11-19 (session 4, slice 1A-4): the hook entry point exists. Changes to this ADR, made as reversible implementation choices and recorded as D32: (a) the internal deadline is **2 s**, not 60 ms — measured p95 is about 17 ms, Phase 0 saw one 565 ms stall, and giving up at 60 ms would silently lose that event; coding is not blocked either way; (b) spooled events are keyed by a generated id (`hook:<uuid>`), because hook payloads carry no reliable message id and two identical prompts must stay two events; replay safety comes from the spool file identity; (c) only the fields listed in `internal/capture` are read from a payload, everything else is dropped; (d) in `ask` mode the SessionStart hook returns a `systemMessage` reminder — not yet observed live. Evidence `evidence/phase-1/1A-4.md`.
- Update 2026-11-19 (session 6, slice 1A-6): hooks are generated by `sessionkeep plugin write` with the absolute path of the binary in exec form; `claude plugin validate` passes; a real Claude Code 2.1.328 print-mode session was captured end to end through them, and the ask-mode `systemMessage` was delivered to the host. Interactive display of that message is not yet observed. Evidence `evidence/phase-1/1A-6.md`.
