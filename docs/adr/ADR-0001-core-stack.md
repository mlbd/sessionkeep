# ADR-0001 — Core stack: Go 1.27 + modernc.org/sqlite, verified at startup

- Date / owner / status: 2026-11-19 / project owner / **accepted** by owner 2026-11-19 (limits listed below still apply)
- Requirement IDs and affected phase: R01, R02, R20, R22; D07; Phase 1 (P1-01, P1-02)
- Decision and constraints: Build the core as one CGO-free Go executable on the Go 1.27 line (1.27.4 at time of writing). Use `modernc.org/sqlite` v1.62.0 with `modernc.org/libc` pinned to the exact version in that module's `go.mod` (v1.80.1). At every start, and in `doctor`, run `select sqlite_version()` and `pragma compile_options`; refuse to open the database in WAL mode if the version is below 3.51.3 or FTS5 is absent, and report `incompatible`. Hide the driver behind the `store` package so it can be replaced.
- Evidence: Go release page (1.27.4, 1.26.11 dated 2026-11-10); Go module proxy (`modernc.org/sqlite` v1.62.0, 2026-11-07, `go 1.26.0`, libc v1.80.1); pkg.go.dev platform table lists SQLite 3.54.1 and a `Backup` type with `Step/Remaining/PageCount/Commit/Finish`; sqlite.org WAL page §11 (WAL-reset bug fixed in 3.51.3, backports 3.44.6 and 3.50.7). All doc-level. Proxy measurements with C SQLite in `evidence/phase-0/README.md` §6. **No Go code was compiled or run.**
- Alternatives and reasons for rejecting them: `mattn/go-sqlite3` (CGO; needs a C toolchain per target and ends simple cross-builds). `ncruces/go-sqlite3` (WASM via wazero; not researched in this session — keep as the named fallback). TypeScript/Node or Bun core (58 ms process start measured for Node on this machine against 13 ms for a native exe; requires a runtime on the user's machine). Rust (viable, but no stated owner preference and slower iteration for this codebase).
- Quality, durability, resource and compatibility implications: Transpiled SQLite is slower than the C build; search and commit latency must be measured before the 300 ms / 100 ms targets are accepted. The exact libc pin means every dependency update is checked against `go mod graph` in CI.
- Security, privacy, licensing and cost implications: BSD-3-Clause driver, public-domain SQLite, BSD-3 Go. The module is maintained essentially by one person; mitigate with the `store` boundary and the fallback above.
- Migration / rollout / rollback / degradation plan: If the spike fails on FTS5, backup or performance, switch driver behind `store` before any schema ships.
- Known limitations, open questions and next review trigger: Embedded SQLite version is stated inconsistently on pkg.go.dev (3.54.1 vs 3.53.4). FTS5 presence, online backup under concurrent write, binary size, windows/arm64 and darwin/linux builds are untested. Review when the Go spike runs or when a new SQLite security fix is published.
- Update 2026-11-19 (session 2): spike run on windows/amd64 — `sqlite_version()` = 3.54.1, `ENABLE_FTS5` present, WAL with one writer and four readers had zero errors, online backup copy passed `integrity_check`, six OS/arch targets cross-compiled at 6.3–6.8 MB. Evidence §9.1. Added constraint from finding B1: backups run on the writer connection or with ingest paused, with a deadline. Still untested: execution on Linux/macOS/arm64, longer soak, fallback driver.
- Approval / supersedes: approved by owner 2026-11-19; refines D07.
