# ADR-0004 — Codex review adapter: `codex exec` on an isolated snapshot

- Date / owner / status: 2026-11-19 / project owner / **proposed** (flags verified locally; no review run)
- Requirement IDs and affected phase: R13, R14, R19; D10; Phase 5 (mock adapter fixture may be built earlier)
- Decision and constraints:
  1. Launch the resolved native Codex binary with an argument array: `exec --sandbox read-only --json --output-schema <schema> -o <result file> --ephemeral --ignore-rules -C <snapshot dir> -`, prompt on stdin. Never pass `--dangerously-*`, `--approve-for-me` or a writable sandbox from this adapter.
  2. **Do not treat the sandbox as the safety boundary.** The reviewer runs against a disposable copy (temp worktree or exported file set) containing only the files the user approved. The adapter records a digest manifest of the real working tree before and after; any difference marks the run `tainted` and is shown to the user.
  3. Probe before use: `codex --version`, `codex exec --help` (required flags present), `codex login status`. Missing flag or not logged in → actionable status, no fallback to weaker options.
  4. Capability and fixture sets are keyed by Codex version; an untested version runs only after the user accepts an "untested version" notice.
  5. Every run needs explicit per-run consent listing the files and context sent. No automatic runs in Phase 5.
- Evidence: local `codex exec --help` and `codex exec review --help` on 0.167.1; `codex login status` → logged in with ChatGPT; non-interactive docs (default read-only, saved auth reuse, JSONL events). Findings C1–C8 in `evidence/phase-0/README.md`. Windows sandbox behaviour is **unknown**: no official page located, conflicting public issue reports across 0.152–0.169.
- Alternatives and reasons for rejecting them: `codex exec review` (simpler, but couples to Git state of the real tree; keep as a second mode once tested). App Server (marked experimental in local help). Depending on `codex-plugin-cc` at runtime (extra required plugin; kept as an optional coexisting workflow).
- Quality, durability, resource and compatibility implications: Snapshot copy costs disk and time on large trees; the file allowlist bounds it. A reviewer without network cannot check current docs; the report must say so.
- Security, privacy, licensing and cost implications: Uses the owner's own Codex login and usage limits; no token files are read. Review content leaves the machine to the provider — consent is per run.
- Migration / rollout / rollback / degradation plan: Adapter is an optional module; absence or failure never affects capture or recall.
- Known limitations, open questions and next review trigger: Whether `-o` can write outside `-C` under read-only on Windows; whether read-only blocks network; whether `--ignore-user-config` should be set (it would also drop the user's model choice). All need the approved synthetic test. Review on every Codex minor version used.
- Update 2026-11-19 (session 2): **decision item 2 is not viable as written on the reference machine.** One real run against a temp-directory repository returned `incomplete`: the sandboxed shell could not start in or read the repository (`CreateProcessWithLogonW failed: 267`, then "Access is denied"). Flags, schema output, `-o` outside `-C` and an unchanged working tree were confirmed. Evidence §9.4. Before this ADR can be accepted it needs: (a) a snapshot location the Codex sandbox identity can read (to be found by test, e.g. a directory outside the user profile), (b) `--ignore-user-config` or an explicit profile so user MCP servers are not loaded into a review, (c) an adapter rule that a run with zero successful file reads is reported as `failed: reviewer could not read target`, never as a clean review, (d) the write and network probes repeated once reads work. Status stays **proposed, blocked on a second approved test**.
- Update 2026-11-19 (session 3): second approved run, repository outside the user profile and `--ignore-user-config` set: every shell command was `rejected: blocked by policy`, verdict `incomplete`, tree unchanged. Evidence §9.6. Requirement (a) above is therefore not solved by location alone, and (b) as tested removes whatever configuration let commands start at all. Two runs, no working review. This ADR remains **proposed and blocked**; it does not affect Phase 1.
