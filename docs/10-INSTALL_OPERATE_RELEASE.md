# Installation, operations and public release

## 1. Installation experience (R01/R20)

Initial target Windows x64 and actual owner environment. Package compiled core + embedded UI + compatible plugin assets; architecture-specific signed archive/installer, no permanent Node/Python/container dependency. Optional parser packs/agents separately disclosed. Distribution order: GitHub Releases binary, documented manual install and Claude Code marketplace, package-manager wrappers only after stable core. npm wrapper if desired downloads a verified matching binary, not required for normal operation. WinGet/Homebrew/Linux packages after policies, package ownership and OS test evidence. No registry listing or public release yet.

One-time onboarding: choose data directory, validate storage permissions/free space, detect host versions and capabilities, preview actual config modifications and user consent, opt in per project and capture policy, optional auto-start, optional agent/provider setup. No login required for core. Show local-only readiness separately from optional features. Record installer version and exact owned entries so repair/uninstall doesn't remove unrelated config. Back up existing settings and use merge not replacement. Never auto-enable global capture. Test fresh/upgrade from supported versions and paths with spaces/non-ASCII characters, restricted privileges and offline install.

## 2. Runtime lifecycle

- `start` uses exclusive per-user OS lock; duplicate launch returns existing status, not second worker. `stop` graceful, preserves queue and checkpoint; explicit force choice targets verified process identity only (PID + created time/executable or native supervisor identity).
- Windows startup via per-user Task Scheduler at login (opt-in, not system-wide elevated service), bounded restart-on-failure, no terminal windows. macOS LaunchAgent and Linux systemd user unit candidates; provide manual fallback for non-systemd systems; test actual environments. OS login not same as machine boot. Hooks never start process per event. Manual mode supports daemon-free capture/read via spool/cache. One engine per OS user, concurrent projects isolated.
- Backoff after repeated failure and display repair instructions. Avoid port collision by validated loopback endpoint selection, file permissions and process lease; don't terminate other apps occupying desired port. Startup migrations under exclusive lock; hook path bypasses with degraded cache/spool. Health states `ready`, `degraded`, `paused`, `starting`, `recovering`, `stopped`, `incompatible`, `storage_full` and optional-module status. Dashboard distinguishes last known and live health.
- Background queue bounded concurrency, event-driven wake-up plus safe periodic reconciliation. Respect low battery/metered connections and resource limits for optional jobs. No continuous polling of all user files. Cancellable work; show pending queue age and low-disk action. Retention and log rotation; no automatic deletion of critical records to reduce CPU/RAM. Show storage breakdown and consent before purging.
- Diagnostic default read-only: install/version, host plugin registration, core lock owner, loopback, DB integrity (light check), storage, spool, last event and capture coverage, optional provider readiness (no paid query), startup settings, latest sanitized error. `doctor --repair` separate explicit action, plan and restore path; never reset existing data silently. Export redacted diagnostics on request, not automatic telemetry.

## 3. Updates and rollback

Opt-in update channel stable/beta; check metadata on schedule or explicit command; no untrusted repository-controlled executable downloads. Verify publisher signature, artifact hash, exact OS/arch, supported update path. Stage binary/assets in separate version dir, create consistent backup and verify disk, stop daemon gracefully, migrate compatible schema, activate atomically where platform supports, smoke check, restore previous binary/config/database as needed with owner permission if reverting loses new writes. Preserve queued events; version protocol negotiation prevents old hooks corrupting new DB. Rollback test must include interrupted migrations, occupied files on Windows and fully offline recovery. Keep previous known good version and release notes. Uninstall disables owned tasks/hooks, stops validated engine, removes owned executable/settings entries, offers export; preserves data by default. Explicit confirmed purge separate, explain native transcript retention.

## 4. Public project and governance

- Working name pending search of GitHub, package registries and trademark risks. Choose owner-approved name and license first. Apache-2.0 proposed, review all direct/transitive deps and optional parsers/models, include required attribution/NOTICE and dependency inventory. Do not claim official Claude/Codex/Graphify affiliation.
- README includes quickstart, actual releases, supported versions/OS, architecture and privacy defaults, troubleshooting, usage costs and limitations. Publish public docs separate from private historical handoff. Add changelog, contribution rules, code of conduct, security contact, support policy and lifecycle/compatibility policy. Use synthetic fixtures and sanitized examples only.
- CI: Go unit/static/race checks where supported, schema/migration/FTS tests, TS lint/typecheck/tests, integration and security suites, OS-specific install/start/recovery/test jobs, benchmark collection. Public forks/PR CI no access to provider credentials. Pin trusted actions and release dependencies, separate protected release jobs, SBOM per binary, dependency scan, artifact checksums and signed/attested builds. Actual signing mechanism and platform trust docs chosen in Phase 0/release spike.
- Release checklist: approval of scope/name/license, no enabled high/critical known issues, measured performance and recall, install/uninstall/update/recovery tested, versioned artifacts, provenance, published limitations and migrations, private files and secrets absent from git and archive. Feature flags default off for unverified integrations. No publication without owner authorization. Use alpha/beta/stable criteria, don't imply all roadmap features delivered.
