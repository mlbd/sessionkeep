Date: 2026-11-20. Machine: reference Windows 10 Pro 22H2 x64, Claude Code 2.1.328. Real runs; nothing mocked. Two live sessions from the pre-approved budget (USD 0.045 each; four of ten used so far). User name replaced by `<USER>`.

`bash scripts/check.sh` → **CHECK PASSED**. New dependency: `github.com/modelcontextprotocol/go-sdk` v1.8.0 (official SDK; licence file states MIT with a transition to Apache-2.0). The SQLite driver pin is unchanged (checked by the gate).

## What was built

- `sessionkeep mcp`: an MCP server on stdin/stdout with four read-only tools — `memory_search`, `memory_get`, `resume_pack`, `project_status`. Each tool runs the same command a person would type, in-process, so scope rules and wording are identical.
- Scope: tools answer for the project the session is in. A model cannot name another project. `all_projects` is refused unless the server was started with `--all-projects`, which only the owner can set.
- `sessionkeep plugin write DIR --with-mcp` adds the server to the generated plugin; without the option the declaration is absent (and removed if it was there). `claude plugin validate` passes with it.
- The command line now accepts `--` to end options, so a query or id that starts with `--` is always taken as text. The MCP tools pass all model-supplied text after `--`.

## Live session 1 — a recall failure

Stored text: "We decided the staging database is refreshed every Tuesday night, and the owner is the data team." Claude Code connected to the server, was offered the four tools, and called:

```text
tool call: mcp__sessionkeep__memory_search {"query": "staging database refresh owner"}
reply: I don't know. The sessionkeep memory search for the staging database refresh and its owner found nothing stored for this project …
```

Claude behaved correctly (it did not guess), but the search was wrong to miss: "refresh" did not match "refreshed" because the index matched whole words only, and every word had to be present.

## Fix

1. Migration `0004_search_stemming`: the full-text index is rebuilt with word stemming, so common endings no longer matter ("refresh"/"refreshed", "decide"/"decided", "migration"/"migrations").
2. When no record contains all the words and the literal match also fails, records containing some of the words are returned, best first, and the result is labelled: `PARTIAL MATCHES ONLY: no stored record contains all of these words …`. Exact mode never does this.

Tests: `TestWordEndingsAndPartialMatches` (including that the fallback stays inside the project and that a total miss is still a miss), `TestStemmingMigrationRebuildsAnExistingIndex` (an index created the old way finds stemmed matches after migrating). One expectation of mine was wrong and corrected: rule-based stemming does not map "slow" to "slowly"; that case is covered by the partial-match fallback, and the test now says so.

## Not built / limits

- No write tools: recording an instruction or a checkpoint through MCP is not offered; the skills do that through the command line, with the confirmation step.
- `instructions_get` and `checkpoint_get` from the plan are folded into one `resume_pack` tool.
- The plugin's `.mcp.json` wiring was validated but the live sessions used `--mcp-config` directly.
- Stemming is English-oriented and rule-based. Search remains keyword search; there is no semantic matching.
- Memory was measured once on one machine. `go test -race` not run yet. windows/amd64 only.
