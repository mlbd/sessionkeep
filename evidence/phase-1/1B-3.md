# Phase 1B-3 evidence — export, import, deletion

Date: 2026-11-20. Machine: reference Windows 10 Pro 22H2 x64. Real runs against real storage; nothing mocked. No Claude Code session was run. `<BOX>` is a throwaway sandbox under the git-ignored `.tools` folder.

`bash scripts/check.sh` → **CHECK PASSED** (adds `internal/archive` and the export/import/forget tests).

## What was built

- `sessionkeep export FILE`: stores waiting events, takes a consistent compacted copy of the database on the writer's connection while holding the lease, verifies the copy (integrity and reference checks), and writes one zip with the database, the settings file and a manifest (format, versions, counts, size and SHA-256 of each entry, and a plain list of what is not included). Never overwrites a file. **Not encrypted**, and says so.
- `sessionkeep import FILE --dry-run`: verifies every entry against the manifest, runs the database checks, and reports what a restore would do. Changes nothing, not even creating the data directory.
- `sessionkeep import FILE`: restores only into a data directory with no database. An older export is migrated forward on first open; a newer one is refused.
- `sessionkeep forget record ID` / `forget captured --project P` / `forget project P`: preview without `--yes`, then permanent deletion, removal of matching events still waiting in the spool, rebuild of the search index, rewrite of the database file, and an audit row holding counts only.
- Dashboard: "Delete this record…", "Delete captured text…" and "Delete project…" buttons that show the same preview and need a second click to confirm. Export and import are command-line only.

## Defects found by tests in this slice

1. **Deleted text survived in the database file.** After `forget`, the marker was still in `sessionkeep.db`. Two causes: the full-text index keeps a deleted row's words in its internal segments until it is rebuilt, and (my bug) the single-record path returned before the compaction step ran at all. `Compact` now rebuilds the index, rewrites the file and empties the write-ahead log, and all three forget paths reach it. `TestForgetRecordRemovesItEverywhere` and `TestForgetProjectRemovesEverythingOfThatProjectOnly` scan every file in the data directory for the marker in any letter case.
2. One tamper test did not actually alter the manifest (wrong spacing in the replaced text) and therefore "passed" an untampered file; it now fails its own setup if the edit does not take.

## Limits

- An export is a plain zip. Anyone who can read the file can read the conversation text in it.
- Deletion does not reach exports made earlier or Claude Code's own session files; the command says so every time.
- "Absent from the database file" was checked by scanning files for a marker string. It is not a forensic guarantee about the storage device (SSD wear levelling, filesystem journals, shadow copies).
- Import restores registered folders as paths from the exporting machine and the exporting machine's device id when the target has no settings. Moving to a different machine or folder layout is Phase 7 work; there is no command yet to re-point a project at a new folder.
- Import refuses to merge into existing data. There is no selective restore.
- `forget` has no "delete everything" form; removing the data directory by hand does that.
- `go test -race` not run yet. windows/amd64 only.
