## Defects found by tests in this slice, and fixes

1. **Hook captures lost while a drain was running.** `TestConcurrentHooksAndDrains` failed: 2–4 of 500 hook writes ended as `roots_cache_unreadable`. Cause: the drain rewrote `roots.json` on every run, and on Windows a reader can fail at the instant a file is replaced. Fixes: the cache is only rewritten when its content changes; readers retry briefly.
2. **Replacing a file that is being read fails on Windows.** A direct test (`TestReplaceWhileReading`, eight readers looping) showed the classic rename returning "Access is denied" even with retries, and still after readers were switched to delete-sharing opens. Fix: `WriteAtomic` now uses a POSIX-semantics rename (`SetFileInformationByHandle` with `FileRenameInfoEx`), with the classic rename as fallback; `ReadFile` opens with delete-sharing, which that rename needs. `TestPosixRenameReplacesAFileThatIsOpen` checks the Windows call directly. This requires Windows 10 1709 or later for the primary path.
3. **Schema:** `sessions` was unique per (agent, device, external session). A Claude Code session whose working directory moves from one project to another could not have been stored. It is now unique per project as well (`TestSessionThatMovesBetweenProjects`). Migration `0001` was edited in place for this — see DECISIONS D34.

## Not run / limits

- `go test -race`: not run (no C compiler). The concurrency tests ran without the race detector.
- Kill points are random process kills, not power loss; disk-full during a drain is not tested.
- The POSIX rename path is verified on this Windows 10 22H2 machine only. Linux and macOS code compiles (`check.sh` cross-compile step) but has not been executed.
- Drain throughput is one `synchronous=FULL` transaction per event; not benchmarked beyond the kill test (67 events stored in roughly the first 150 ms).
- There is no background drain: with no engine, events wait in the spool until `sessionkeep ingest` runs. Slice 1A-6 decides when the plugin triggers it.
- Events captured before a project was paused or set to `off` are still ingested; only exclusions discard already-spooled events.
- Quarantined files are kept indefinitely; no command lists or purges them yet.
