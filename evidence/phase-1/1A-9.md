## Defect found by a test, and fix

`TestResumeWarnsWhenTheCodeMovedAndTouchesNothing` failed: rewriting an **untracked** file after a checkpoint produced no warning, because the uncommitted-state fingerprint covered only `git status` and `git diff HEAD`. The fingerprint now also includes the content of untracked, non-ignored files (up to 2,000 files and 4 MB each; beyond that, size and modification time). `TestReadAndCompare` checks that a modified tracked file, a new untracked file, a rewritten untracked file and a staged change all give different fingerprints, and that an ignored file gives none.

What this shows: Claude chose the `resume` and `recall` skills unprompted, reported the checkpoint, the next step and the stored decision correctly, and said plainly that there was no Git state to compare. Two details to note: Claude capitalised the first letter of the instruction text in its preview, a small departure from "the user's own wording"; and six events were still in the spool at the end because the session ended before the last background drain finished.

## Not built / limits

- A checkpoint is a note plus Git state. There is no task object, no plan, no link from a checkpoint to requirements (those are Phase 5/6 items in the spec).
- `resume` shows the six most recent user/assistant texts, each cut to 600 characters, and the three newest checkpoints.
- Git is read through the `git` program; if it is missing the checkpoint still works and says there is no Git state. Submodules and worktrees are not treated specially.
- `go test -race` not run (no C compiler yet — scheduled for slice 1B-5). windows/amd64 only.
