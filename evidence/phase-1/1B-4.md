# Phase 1B-4 evidence — install, uninstall, auto-start, doctor

Date: 2026-11-20. Machine: reference Windows 10 Pro 22H2 x64, Claude Code 2.1.328. Real runs; nothing mocked. No model usage (the Claude Code commands used here manage plugins and do not start a session). `<BOX>` is a throwaway sandbox under the git-ignored `.tools` folder.

`bash scripts/check.sh` → **CHECK PASSED** (adds `internal/install`, `internal/autostart` and the install tests).

## What was built

- `sessionkeep install [--with-mcp]`: copies the running program to `%LOCALAPPDATA%\Programs\SessionKeep` (other systems: a per-user folder under the home directory), generates the plugin and a one-plugin local marketplace beside it, writes a record of every file it created, creates the data directory, and prints the two Claude Code commands that enable the plugin. **It edits no Claude Code setting.** Running it again updates in place; it refuses a non-empty folder it did not create.
- `sessionkeep uninstall [--purge-data] [--yes]`: removes exactly the recorded files, the logon entry and the folders it emptied; keeps anything else in the folder; keeps all data. `--purge-data` shows what is stored and needs `--yes`, and refuses a directory that is not recognisably SessionKeep's.
- `sessionkeep autostart enable|disable|status`: optional per-user logon entry that stores waiting events once at logon.
- `sessionkeep doctor`: now also checks that the installed program exists and that every hook in the generated plugin points at a program that exists.

## Things that did not work as first designed

1. **Logon task.** The first implementation created a logon-triggered scheduled task, as agreed. Windows refused: `ERROR: Access is denied.` — a logon trigger needs administrator rights. Auto-start now uses the current user's "Run at logon" registry list instead, which needs no elevation and affects no other user (DECISIONS D66). The entry runs the program through `conhost --headless` so that no console window should appear.
2. Test setup, not product: three tests failed because the test sandbox defined no install location, which made `doctor` report a failed check; every test sandbox now has its own install folder, so no test can see or touch a real installation.

## Not done / limits

- **Not installed for real.** By the owner's choice the real install is theirs to run. The real `%LOCALAPPDATA%\Programs\SessionKeep` and the real data directory still do not exist.
- The logon entry was created, read back, executed by hand and removed. It was **not** exercised by an actual Windows logon.
- When `uninstall` is run from the installed copy on Windows, the running program cannot delete itself; it is moved to the temp folder and the command says so. That path is implemented but was not exercised (the test runs uninstall from the build output).
- No signing, no update mechanism, no rollback, no package-manager installers; those are Phase 8.
- Auto-start exists for Windows only; on other systems the command says it is not available.
- `go test -race` not run yet. windows/amd64 only.
